## Seguridad de firma — límites explícitos

`MpSignature` expresa requisito de auth; un apiKey header en OpenAPI no implementa criptografía. Request debe verificar firma oficial del manifiesto que liga query `data.id`, `x-request-id` y timestamp firmado **antes de inbox/job**; header presente no es firma válida. La igualdad query↔body decimal canónica se valida aparte: JSON Schema del body no accede a query. Hash RFC8785 del body allowlist para inbox no es firma ni prueba de autenticidad. Nunca firmar/assertar autenticidad usando fixture sintética ni reenviar valores/body rechazados a logs/métricas/colas.

Algoritmo exacto, construcción/codificación del manifiesto, normalización oficial, unidad de timestamp, ventana replay/tolerancia, rotación de clave y compatibilidad204 quedan DR-05 hasta evidencia de modalidad contratada; **no** elegir secretos/algoritmo/ventana inventados ni habilitar adapter real con esta prosa. Replay auténtico admitido por esa policy recorre dedup durable; fuera de ventana oficial rechaza auth. AC-GOAS-SEC: firma ausente/inválida/manifiesto alterado/expirada→401 TOKEN_INVALID, cero inbox/job/dinero; firma válida+query/body discordantes→400 WEBHOOK_ID_MISMATCH, cero inbox/job. Fixtures de firma sanitizadas y ejecución son DR-05, no esta validación sintáctica.
