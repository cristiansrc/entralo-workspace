# ADR-006 — Stack contract-first, runtime y entrega federada

- **Estado ADR:** `proposed`; **Lifecycle status:** `draft`; revisión `revision-needed`.
- **Fecha:** 2026-10-01; **Owner:** plataforma/seguridad y responsables backend/frontend; autor Planner.

## Contexto
Kotlin/Java21/Boot4/PostgreSQL/JPA/Flyway/API-first/Gradle y React Vercel/GitHub CI confirmados. Runtime/región/IaC seleccionados como recomendaciones del paquete [propuesta](../architecture-proposal.md), no aprobados por humano; generación Boot4 debe sustentarse sin contaminar dominio.

## Decisión propuesta
Baseline Spring Boot4.1.1+Java21; Kotlin>=2.2 estable BOM y PostgreSQL18.x propuestas verificadas upstream, pin exacto de Kotlin/Gradle/generator/driver/Flyway antes spec ejecutable. Generador `spring` Java con `useSpringBoot4/useJackson3/interfaceOnly`, implementación Kotlin/mapping a dominio, sólo `build/generated/openapi`; fuente `docs/api/openapi.yaml` por repo futuro. Comando exacto/config en landscape §6, no Gradle script creado/ejecutado.

**R-9, contraste oficial 2026-09-30:** documentación estable Boot4.1.1 Java17–26 incluye21; JDK27 GA **no-LTS**, Gradle9.8 sí soporta27 pero no amplía matriz Spring. Context7 devuelve main con27: precedencia de documentación de release estable4.1.1, no actualizar baseline a27 por rama de desarrollo. Java25 **ya LTS** candidato a upgrade futuro del proyecto con pruebas/dependencias/licencia, no cambio confirmado de Java21. Kotlin y Gradle se pinnean a releases exactas compatibles posteriormente; rangos son evidencia de discovery, no configuración productiva. Fuentes landscape S1/S6/S7/S12; roadmap Oracle distingue vendor/distribución/updates, no prometer soporte de todo OpenJDK.

**RUN-01 ECS Fargate seleccionado P**, APIs mínimo2 tasks/2AZ prod y workers críticos redundantes/leases, escala independiente. **DATA-01 una RDS PostgreSQL Multi-AZ DB instance/seis DB lógicas**, pools presupuestados, no PITR lógico independiente. **REGION-01 us-east-1 primaria propuesta**, comparación RTT Colombia/us-east-1/sa-east-1/mx-central-1 y cuenta/compliance antes fijar deployment; DR backup-restore us-east-2 propuesto. **IAC-01 Terraform seleccionado**, repo platform/estados-entornos aislados, S3 cifrado/versionado+use_lockfile (locking DynamoDB Terraform deprecado), providers/CLI pins bootstrap; no CDK mixto. Coste/licencia/retención/región y RDS18 minor real verificados antes runtime. Defaults no decisiones humanas aceptadas.

**BFF AWS Kotlin seleccionado P** con React Vercel y transporte Node/TS mínimo same-origin OIDC→STS/SigV4, no rewrite simple como guard; store DynamoDB por canal/refresh CAS, detalle ADR003. BFF completo Vercel Node alternativa no elegida. **R-8** módulos/worker Purchases separados en capacidad/presupuestos sin séptimo contexto. GW-01 REST/WAF, ID-01 pools separados y BFF-01/02 quedan elegidos dentro del plan, aprobación global pendiente.

GitHub Actions→OIDC federation→STS roles por repo/entorno y aud/sub exactos; credenciales efímeras, nada de access keys largas. Verificar formato real subject vigente con ids inmutables cuando aplique. Pin actions por commit, environments protegidos, build una vez/promoción digest, tests/contracts/SBOM/security, migrations expand/contract y rollback compatible. Vercel buyer/admin separados, no previews con PII/secretos prod. Esto no crea Git/pipeline ni aprueba plan.

## Alternativas
Lambda reduce costo idle pero requiere evidencia cold-start, pools y workers/job handling, no ejecutar saga en una invocation. EC2 permite control con mayor operación. EKS no justificado sin capacidad Kubernetes/equipo/caso actual. Java27 descartado para baseline por Boot compatible sólo17–26 aunque Gradle9.8 soporta27. DTO Kotlin generator no se asume Boot4 sólo porque `spring` sí documenta soporte. Credentials largas descartadas por riesgo/rotación.

## Consecuencias y criterios
Fargate costo fijo/infra; Lambda benchmark alternativa, no afirmación de mala escala. ADR6-AC1: command genera sólo en build, salida compila/interopera y serializa contra OpenAPI fuente, regenerate sin diff no determinista. ADR6-AC2: rol deploy no puede ser asumido desde repos/origins/env no autorizados; cero keys AWS largas. ADR6-AC3: release/restore no rompe contrato ni repite MP; pools soportan réplica máxima y prueba carga acordada. ADR6-AC4: version pins reales/RDS región se verifican antes ejecución, no usar docs master como versión instalada.

Fuentes actuales y alcance de refresh propuesta §15; Boot4.1.1 Java17–26 directamente verificado, Java21 confirmado, pin Kotlin posterior. R-9 Gradle/JDK adicionales son referencias históricas no reconsultadas en esta ronda. Runtime/IaC recomendados en plan único pendiente aprobación, dimensionamiento real posterior.

## I-2 — bootstrap y evolución de aislamiento físico

Conservar DATA-01 una RDS Multi-AZ/seis DB lógicas iniciales; **no separar Purchases ahora sin carga/coste probados**. Coste menor vs failover/CPU/IO/WAL/locks/mantenimiento/PITR conjunto, no independencia física. Bootstrap endpoint/roles/secrets por owner, pools API+workers+max tasks/rolling/Flyway<=70% quota conexiones real, bulkheads para avisos/PDF/cadena; load H-C+acceso+I-28+polling/DR y factura1/2/3/6 instancias antes prod. Si trigger por shared contention, aislar antes go-live; tres ventanas5min SLO/error/headroom insuficiente/DR incumplido, integridad/deadline incidente inmediato sin esperar. Hotness define Purchases/Ticketing/Payments primero, resto después evidencia. Cutover writer único/pausa/replicación/checks/fences/outbox+inbox+MP+uso/endpoint owner/smoke; rollback tras escrituras sólo sincronización inversa auditada, no DNS ciego. Coste doble capacidad/ventana medidos, sin zero downtime prometido. ADR6-AC6/I2-AC01–04/propuesta §11.1 constituyen acceptance; no IaC/migraciones creadas, ADR proposed.

**Prerrequisitos SAR-05/12:** cuotas reales Cognito/SES/Gateway/Identity/KMS/STS/DynamoDB/SQS y budgets separados/matriz carga+30%headroom, renovación principal proactive, lease crítico5s/tick1s/dos réplicas. CI platform Checkov pin/bootstrap/review plan deny high/critical no resuelto; contratos productor/consumidor entre repos compatibilidad CI y promoción digest con versiones registradas, breaking sin coordinación bloquea. Pools max tasks+rolling/Flyway<=70% max_connections efectivo, RDS Proxy sólo benchmark/presupuesto demostrado; fixture generator/Boot4/Jackson3/Kotlin compile/serialize/errors/nullability/decimal pin bloquea bootstrap si falla. SAR12-AC evidencias/tests futuros propuesta§17, no pipeline ejecutado. Ingress/cookie/MFA/offline/clock/credits matriz§16; credits cloud no buyer refund/SLO garantía. Context7 actual PostgreSQL datetime/AWS policies/visibility, baseline stack no upgrade.

## Recuperación y coste operativo
Propuesta §11: RDS backups35d/PITR, restore trimestral nueva instancia física, conciliación antes replay/pagos/refunds/emisión/uso; DynamoDB restore invalida sesiones, no revive tokens. Multi-AZ HA no DR. Objetivos P instancia/AZ RPO5min/RTO60min, regional backup-restore diario RPO24h/RTO8h, writer único/fencing, sin active-active inventario. RTO incluye conciliación/Cognito recuperación validada; objetivos no pruebas ni garantías AWS. Presupuesto Fargate/RDS/WAF/ALB/NAT/egress/KMS/telemetría/Vercel/chain y asignación guardia antes prod. ADR6-AC5: simulacro registra pérdida/tiempos y cero doble desembolso/acceso, incumplimiento genera revisión no SLA ficticio.
