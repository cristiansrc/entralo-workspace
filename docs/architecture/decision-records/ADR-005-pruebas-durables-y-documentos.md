# ADR-005 — Prueba durable no bloqueante y separación documental

- **Estado ADR:** `proposed`; **Lifecycle status:** `draft`; revisión `revision-needed`.
- **Fecha:** 2026-10-01; **Owner:** Ticketing/Blockchain, seguridad/producto, Purchases/operación fiscal; autor Planner. Proveniencia histórica conservada: corrección F-C/F-D de ronda 2026-10-01, origen 2026-09-30.

## Contexto
R-06 separa prueba de emisión/estado operativo y exige pending hasta confirmación; usuario exige ejecución durable sin bloquear compra. R-09 define vendedor Entralo, factura externa manual y PDF local NO fiscal, sin proveedor/API fiscal.

## Decisión propuesta
Outbox emisión Ticketing→inbox/obligación Blockchain persistidos. P-02 **Merkle batching recomendado dentro del plan**, N100/T15min primer umbral, raíz/miembros/intent antes envío, inicial+3 retries1/5/25min, reconciliación/redrive auditado sin descartar obligación. Formato criptográfico versionado bajo revisión. Finalidad/red/proveedor/custodia firma/costos son gate de contrato productivo posterior, no Polygon heredado ni pregunta para cerrar boundaries. Reorg pending; durabilidad obligación recuperable, liveness depende proveedor/fondos/operación. Detalles y gates [propuesta §§9/10](../architecture-proposal.md), sin aprobación humana/publicación implícita.

P-03 dominio/secreto alta entropía, raw/QR/PII/ref pago/orden nunca públicos. SAR-10 I-25 pre-gate allowlist operational_status/proof_status/proof_as_of redondeado abajo minuto UTC o null sin observación/error R-06; no batch/tx/hash/leaf/root/proof/timestamps finos/metadata I-16. Threat model enumeración/correlación/tiempos/payload/redacción+acta seguridad/producto **antes** exposición, no no-vinculabilidad demostrada. Ticketing superficie única/proof view async/no query cadena pública, caída503/no vigente inferido. SAR-06 elimina grant staff: token/aserción existente/IAM+permiso Identity actual action/event/device y uso fuerte/key admission_attempt_id. Cache informativa, no offline; contingencia manual lista/escritor único/partición/carril aislado/registro antes ingreso/ACK reconciliación, sin lista/aislamiento detener. DOOR-01…04, SQS retención no borra obligación.

Purchases genera PDF **«Comprobante de compra — NO fiscal»** tras confirmación, privado S3; factura/nota crédito DIAN/CUFE emitidas/enviadas manualmente externo a solicitud. Registro `SOLICITADA/EN_GESTION_EXTERNA/EMITIDA_Y_ENVIADA/ERROR_PENDIENTE` propuesto desde brief, CUFE/evidencia sólo verificados, revisión diaria. Capturar titular sólo si solicita. Catalog P-04 config fiscal versionada/Purchases snapshot sin tasas universales. DR-05/DR-07 go-live siguen abiertos, no bloquean diseño ni reabren emisor/legal defaults.

## Alternativas y consecuencias
Anclaje sync checkout descartado por bloqueo/disponibilidad. Fire-and-forget descartado por pérdida. NFT/wallet fuera alcance. Hash de datos enumerables y raw proofs públicos descartados. Facturación API/fiscal local descartada V1; no confundir PDF con factura. Cadena no se elimina por refund ni implica vigencia, retención sensible/legal todavía requiere política Q-N05.
